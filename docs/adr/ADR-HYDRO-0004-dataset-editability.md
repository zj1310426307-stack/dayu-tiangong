# ADR-HYDRO-0004：数据版本状态与人工只读权限解耦

- 状态：Accepted
- 日期：2026-09-09
- 取代范围：数据版本“发布/批准状态自动等于只读”的旧规则

## 决策

`DatasetVersion.status` 只表达草稿、审核、批准、发布、退役或驳回等业务流程状态，不再决定数据能否编辑。数据写权限由独立字段 `is_read_only` 决定，且所有既有和新建版本默认 `false`（可编辑）。

用户可在全局版本选择器中执行“设为只读”或“解除只读”。后端仍在事务内锁定 Dataset Version 行；当且仅当 `is_read_only=true` 时拒绝河网、断面、建筑物、Marker、参数、边界和计算方案等版本化数据写入。只读版本必须允许执行解锁动作。

## 状态一致性

编辑已批准、已发布、已退役或审核中的数据时，后端把版本重新标记为 `draft`，清除内容哈希及审核、批准、发布和退役时间。这样用户始终有编辑权，同时旧认证不会错误覆盖新内容。再次用于 Standard 1D 权威计算前，必须重新校核并批准；批准本身不打开 `is_read_only`。

## Standard 1D 计算门

`draft` 版本不能直接生成 Standard 1D 权威输入快照。水动力页面在收到 `DAYU_DATASET_NOT_AUTHORITATIVE` 时直接提供“校核并批准当前版本”入口。批准校核要求错误为 0 且模型就绪；工程复核警告不阻断本项目明确的未率定方案计算，但会作为警告展示并写入批准原因。批准后版本仍可编辑，任何后续数据写入都会撤销批准并回到 `draft`。

计算任务的 `input_snapshot`、哈希、运行结果和发布审计记录不属于“数据版本编辑锁”。它们继续不可原地改写，以保证既有成果可追溯。

## 删除语义

非只读数据版本允许删除。版本直属河道、断面和其他 `ON DELETE CASCADE` 数据随版本在同一事务删除；`public.river.dataset_version_id` 的历史 `RESTRICT` 约束改为 `CASCADE`，修复“版本内存在河道即无法删除”的错误。

如果版本仍被计算任务、发布记录、派生版本或生产审计引用，数据库关系门继续拒绝删除。用户应先处理这些显式引用；平台不得为了完成删除而静默抹除历史运行证据。

## 前端

- 所有版本均显示独立的“业务状态”和“编辑权限”。
- 顶部提供“设为只读/解除只读”。
- 删除按钮不再只对 `draft` 展示，而是对所有非只读版本展示。
- 页面写控件统一读取 `is_read_only`，不再从 `status` 推断。
