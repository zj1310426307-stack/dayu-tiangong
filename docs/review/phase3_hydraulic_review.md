## 2. 数值方法说明

求解变量为过水面积 `A` 和流量 `Q`。对矩形等效断面，质量方程和动量方程采用一维 Saint-Venant 守恒形式；通量为：

- 质量通量：`F₁ = Q`
- 动量通量：`F₂ = Q²/A + gA²/(2B)`
- 源项：`gA(S₀ - S_f)`
- 摩阻坡降：`S_f = n²Q|Q| / (A²R^(4/3))`

空间离散使用局部 Lax-Friedrichs（Rusanov）数值通量，内部控制体采用相邻断面间距的平均值，时间采用显式推进。横断面点集在本阶段转换为“宽度 + 最低床面高程”的矩形等效断面，糙率读取 Phase 2 版本化断面数据。

初始条件支持统一初始水位和初始流量；若未指定初始水位，则优先取下游水位边界首值，否则取最高床面以上 1 m。上游流量和下游水位边界按时间线性插值；边界缺失时使用零梯度回退，并在诊断中明确记录。

## 3. 输入输出检查

输入为 Phase 2 的不可变计算方案快照 `dayu.model-input.v1`，包含河道、拓扑节点、河段、横断面、糙率、边界条件、闸门、泵站和模型参数。每条可计算河道至少需要两个桩号严格递增的断面。

网格明确构造：

- `Node`：断面所在的一维计算节点，位置为米制桩号；
- `Element`：连接相邻节点，长度为下游桩号减上游桩号；
- `Section`：断面编号、河道、桩号、等效宽度、床面高程和糙率；
- `RiverMesh`：单河道有序节点、单元、断面与拓扑端点。

空间对象统一存储为 CGCS2000（EPSG:4490）。由于 EPSG:4490 是地理坐标系，求解器严禁直接用经纬度差计算水动力距离，而使用断面桩号和河段长度（m）。Cesium 直接显示 EPSG:4490 的经纬坐标。

输出契约为 `dayu.hydraulic-result.v1`，对每个断面给出对齐的 `time`、`water_level`、`flow` 和 `velocity` 数组；数据库按“任务—断面—时刻”持久化，同时保存求解器标识、坐标系、距离口径、CFL、步数、干涸钳制、边界存在性和库容变化等诊断。

## 4. 计算稳定性检查

稳定性控制包括：

- 自适应时间步：`dt ≤ CFL × min(dx) / max(|u| + √(gh))`；
- CFL 参数限制在 `(0, 1]`，默认 0.75；
- 时间步同时受用户请求值、下一输出时刻和剩余模拟时长约束；
- 最小水深和最小过水面积钳制，出现干涸时流量归零；
- 非有限波速、非有限状态、极小时间步和最大迭代步数均触发显式失败；
- 初始水位低于最低安全水深时自动抬升，并记录 `initial_water_level_adjusted`；
- 诊断记录实际最大 CFL、最小使用时间步、降步次数、最大波速和相对库容变化。

自动化覆盖单河道、近稳态、洪水过程、自适应 CFL、闸泵占位、输入快照、API 生命周期和结果持久化。最终全量回归为 30 项通过，未出现 NaN、无穷值或空成功结果。

## 6. 性能测试

在本机 Docker Compose 演示环境中，以 20 个断面、3600 s 模拟时长、300 s 输出间隔执行一次同步运行：

- 输出时刻：13 个；
- 持久化结果：260 行；
- `POST /run` 实测响应耗时：81.33 ms；
- 前端生产构建、类型检查均通过；
- npm 安全审计：0 个已知漏洞；
- 浏览器：任务配置、任务监控、三条 ECharts 曲线和 GIS 断面跳转全部可操作，控制台 0 error / 0 warning。

Cesium 约 4.19 MB、ECharts 约 1.14 MB，均已按路由/页面动态加载：非 GIS 页面不预载 Cesium，未打开结果图表时不加载 ECharts。物理构建块仍较大，属于已知性能边界。

## 7. 存在问题

1. 横断面采用矩形等效，尚未按原始断面点进行非规则断面分层积分。
2. 各河道独立求解，现有拓扑用于识别端点，尚未实现主支流汇流节点的质量/动量耦合。
3. 缺少边界的演示支流使用零梯度回退，适合软件闭环验证，不代表工程边界设置。
4. 闸门和泵站仅计算静态能力预览，尚未作为内部边界耦合到计算单元。
5. 任务目前在 API 进程内同步执行，尚无队列、并行 worker、取消、超时和重试机制。
6. 尚未使用实测水位流量进行糙率率定、灵敏度分析和工程基准对比。
7. 质量守恒以相对库容变化提供诊断，尚未建立工程项目的分级告警阈值。
8. Cesium/ECharts 已延迟加载，但大型独立构建块仍会影响首次进入对应页面的下载时间。

因此，本阶段成果可用于架构联调、算法演进和 DEMO DATA 验证，不可直接作为防洪调度或工程设计结论。

## 8. Phase4闸泵联合调度建议

1. 实现汇流节点质量守恒与水位/能量兼容条件，形成真正的河网联合求解。
2. 将闸门孔流/堰流、泵站特性曲线和启停状态作为内部结构物边界，并覆盖淹没、倒流和限流状态。
3. 建立异步任务队列与独立计算 worker，支持排队、取消、超时、重试、资源配额和可恢复执行。
4. 把调度规则、启停约束、闸门开度变化率和设备能力做成版本化输入，禁止以固定边界值替代控制决策。
5. 引入“防洪安全、供水保证、能耗、调度平滑度”等多目标评价，先做规则模拟，再接入优化器。
6. 接入实时遥测前先建立质量标识、缺测补全、时间对齐和人工确认机制，实时数据不得覆盖原始归档。
7. 增加标准算例、实测过程率定、河网质量平衡、结构物耦合、重启恢复和性能基准测试。
8. 在界面中区分“方案输入、模拟结果、优化建议、人工批准”，任何自动建议都必须保留解释、版本和审计轨迹。
