## 4. 河网验证

### 4.1 Branch 与桩号

已接纳的每个河段片段内部桩号严格递增，源几何顺序与测量桩号顺序一致。逐河段长度、末桩、

### 4.2 生产失败门禁：不连通拓扑

真实 PostGIS 拓扑结果包含 **3 个不连通分量**，没有形成任务书要求的汇流节点。各分量之间
的空间缺口明显超过项目拓扑容差；精确距离与坐标未发布。

因此不能通过放大吸附容差、手工平移或补画无依据连接线伪造连通。必须补充权威中心线/连接段，
或重选满足验收拓扑的案例。本项为 **FAIL / NO-GO**，不是普通待办。

## 6. 模型验证

### 6.1 已完成的软件边界加固

- public 与 hydraulic 身份不同时，v3 边界、闸、泵和调度观测对象通过数据版本、几何、河道身份、
  有向端点或复合外键校验后显式映射；缺映射或未知对象立即失败。
- v3 适配器按 HydraulicReach 生成求解段与连接，不再把多 Reach Branch 静默压成一段。
- v3 产物生成器从同一冻结快照生成网络、河段、断面、Profile、边界、来源和 manifest，避免
  分别查询导致版本漂移。
- 水面线 GeoJSON 只接受成功任务和精确时刻，并明确不使用河道 buffer 伪造风险范围。

### 6.2 真实案例模型状态

本案尚未建立当前片段与既有模型断面、上下游边界、建筑物和同工况的一一对应。因此：

- 未伪造 SimulationCase 或 BoundaryCondition；
- 未生成真实案例 `dayu.model-input.v3`；
- 未运行求解器，NaN/Inf、CFL、收敛和水量平衡均为 `NOT_EVALUATED`；
- 未生成 ΔH/ΔQ/ΔV，模型对比保持 `BLOCKED / NO-GO`。

现有求解路径仍是简化 continuity-Manning 求解，不能冒充生产 Saint-Venant 动量方程验收；
真实三区糙率和查算表进入求解器的科学一致性也未通过。这两项需在后续模型阶段单独验收。
