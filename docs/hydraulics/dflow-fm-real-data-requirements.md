## 使用原则

本清单是资料入场与证据追溯要求，不是一组建议参数。任何未知值都必须保持 `UNKNOWN`，不得用 0、1、设计值、典型值、HYDROLIB/D-Flow 默认值或其他项目参数代填。

每个数值、布尔状态、曲线、几何、时序和标识都必须指向可定位的证据记录。对应现行 solver-neutral 合同：

- `SOURCE_DATA`：来自已识别源数据的值。如果经转换或推导，`evidence` 还必须记录原始来源、转换方法、执行工具/版本和输出 hash；
- `SYNTHETIC_ASSUMPTION`：只能进入隔离的合成 fixture/benchmark，不得作为真实工程率定、验证或生产输入；
- `UNKNOWN`：不带数值，也不能在导入、生成、编译或运行中被静默补齐。

原始文件必须不可变保存，清洗/转换结果作为新 artifact 交付，两者分别计算 SHA-256。不得覆盖原始文件，不得用“最近点”、名称模糊匹配或隐式插值建立资产身份。

## 整包 Manifest 与通用元数据

交付包必须有一份机器可读 manifest，并对每个文件或数据表记录以下内容。物理文件名由资料提供方确定后写入 manifest，本文不预造文件名或默认值。

| 字段组 | 必须记录的事实 |
|---|---|
| 数据身份 | 唯一 dataset/artifact ID、版本/修订号、文件相对路径、格式与 schema 版本 |
| 完整性 | 文件字节数、SHA-256、生成/导出时间，以及包级 manifest 的 hash |
| 责任与来源 | 数据所有者、保管人、提供组织、源系统/设备/图纸/测量任务、采集方法和联系人 |
| 时间 | 数据覆盖起止时间、原始时区及 UTC offset/DST 规则、采样时钟同步方式、采样间隔与不规则采样标记 |
| 空间与高程 | 水平 CRS/EPSG 或完整 WKT、坐标单位、垂直基准、高程单位、大地水准面/本地零点及已审查的基准转换参数 |
| 物理语义 | 每列名称、物理量、单位、正方向、参考面、标识符规则和枚举定义 |
| 质量 | 仪器型号/序列号、校准记录、精度/分辨率/不确定性、缺测和异常码、人工修改与 QA 结论 |
| 处理链 | 原始输入 hash、转换/清洗/插值/基准换算方法、脚本或工具版本/commit、执行参数与输出 hash |
| 权限与许可 | 授权范围、保密级别、保留期、再分发限制、许可/合同依据与审批人；私密凭据不得写入文件 |
| 审查 | 提交人、领域审查人、审查日期、已知限制和接受/拒绝结论 |

每个“不适用”必须写明不适用原因并由领域审查人确认，不能用空值代替。

## Network 河网与断面

| 资料类别 | 必须提供 | 主要审查点 |
|---|---|---|
| 节点与汇流点 | 权威节点 ID、节点类型、x/y 坐标、连接分支、外部边界/内部节点身份 | ID 唯一；拓扑与坐标一致；不存在未解释的断头、悬挂或自连接 |
| 分支 | 权威 branch ID、from/to node、水流/正 chainage 方向、完整 LineString/测量轨迹、物理长度、里程起算关系、测量日期 | 几何长度、工程里程与断面/设施 chainage 之间必须有可审计的对应；方向不得猜测 |
| 断面 | 断面 ID、branch/chainage、测线、station-elevation 或 XYZ 原始点、左/右岸定义、底高程、测量日期、垂直基准、处理后断面与原始点的 lineage | 点序、单位、基准和左右岸方向一致；重叠/交叉/突变、水面以下覆盖和断面间距通过专业 QA |
| 粗糙率 | 所用公式类型（如 Manning/Chezy，由项目资料明确）、数值、单位/维度、空间区段、季节/流态适用性、调查或率定依据 | 不得把不同公式的数值直接复用；未覆盖区段保持 blocked，不做默认延伸 |
| 设施与观测定位 | 每个闸、泵、边界、测站和观测点的权威 ID、branch/chainage、坐标、上/下游方向与定位来源 | 必须精确绑定；禁止最近分支/断面/观测点推断 |
| 蓄滞与侧向连接 | 蓄滞区/水面-容积关系、侧向汇入位置与分配方式、支流和连通设施 | 当前 D-Flow Adapter 不验证侧向汇入；如工程存在，必须交付并单独阻断，不得删除后声称模型完整 |
| 网格/离散依据 | 网格目标、局部加密区、最短边/定义点保护依据与敏感性方案 | `mesh_edge_length_m` 是需要证据的模型选择，不得从仓库或其他模型默认复制 |

导入前应由水力专业人员确认拓扑方向、分支长度、断面覆盖、粗糙率分区、设施位置、边界数量和高程基准。任何自交、断线、重复 ID、空间/里程冲突必须在入库前有处理记录。

## Gate 闸门

每座闸及其每个独立可控孔口都必须保留权威身份，不能在交付时先合并成一个无法追溯的等效闸。

| 类别 | 必须提供的真实资料 |
|---|---|
| 身份与位置 | 设施 ID、孔口 ID、名称、工程管理编码、统一 HydraulicStructure 身份、branch/chainage、坐标、上/下游方向、设计/竣工/改造图版本 |
| 类型 | 闸型、启闭方式、过流模式、孔口数、各孔是否同型、实际流向和反向过流可能性，并附图纸/技术资料作为 subtype 审计证据 |
| 几何 | 底槛/门槛高程、净宽、孔口宽度、门叶高度、门槽/流道几何、最小/最大开度、开度轴向、参考高程、门下缘高程与全部垂直基准；`general_opening` 还需完整上下游分段宽度/高程、crest length、gate opening width 和水平开启方向 |
| 水力参数 | 实际采用的流量/修正系数及来源、适用流态和标定范围；`vertical_underflow_gate` 需有来源的 correction coefficient；`general_opening` 需正/反向、自由/淹没的 Gate 和 Weir 系数、正/反向收缩系数及 extra resistance；是否考虑 velocity head 必须由工程资料决定 |
| 执行机与约束 | 控制方式、命令值到物理开度的标定关系、分辨率、死区/回差、最小/最大开度、启闭速率、最短保持、限位/联锁、手动/自动模式和故障状态 |
| 初始状态 | 每次事件/运行开始前的实测开度、执行机模式、可用性、状态时间戳和数据质量；不得沿用 Static Preview 的“全关”假设 |
| 实际运行 | 带统一时钟的命令记录、开度反馈/实际开度时序、手动操作、状态/故障/联锁事件和维护变更记录 |
| 配套实测 | 闸上/闸下 H(t)、断面 Q(t)或经审查的闸流量推求、观测点身份/位置/基准/不确定性、闸门命令与水力时序的时钟对齐证据 |

现行 Adapter 只审计了 `vertical_underflow_gate -> Orifice` 和完整 `general_opening -> GeneralStructure` 两个受限子集。其他闸型、参数不全、系数无来源、流向不明或高程基准不统一时必须停止映射，不得改用另一 subtype 或接受 native 默认系数。

## Pump 泵站

| 类别 | 必须提供的真实资料 |
|---|---|
| 身份与位置 | 泵站 ID、每台机组 ID、统一 HydraulicStructure 身份、branch/chainage 或池/河道连接身份、进/出水口 ID、坐标、进/出水高程和垂直基准 |
| 转输语义 | 明确分类 `inline_branch`、`inter_basin`、`external_inflow` 或 `external_outflow`，记录吸水端、出水端、正方向、系统边界归属及在质量平衡中的项别 |
| 机组 | 实际机组数、每台型号/叶轮/转速或频率范围、相同/非相同机组组合、设计流量、设计扬程、运行区间、进出水管/阀门特性和资料版本 |
| Q-H 曲线 | 每台机组在对应转速/频率/叶轮配置下的原始 Q-H 点列、测试或厂商证据、单位、允许工作区、不确定性与修订版本；站级聚合曲线必须同时交付从单机到聚合的推导方法 |
| Head-reduction 映射 | 若使用现行 D-Flow native Pump 表示，提供由有证据 Q-H 曲线得到的 head/reduction-factor 点、参考 aggregate capacity、转换公式/工具版本、输入/输出 hash 和专业审查结论 |
| 效率与能耗 | 每台机组效率曲线/效率面、电机/变频效率、输入功率、电量与测量方式；没有效率数据时不得生成能耗结论 |
| 控制语义 | 现场命令是否为机组台数、单机启停、频率/转速、目标流量或站级 aggregate capacity；命令到 native target 的转换只能在有工程证据时定义 |
| 可用性与约束 | 每机组可用/停役/检修状态，最小/最大可运行机组数、最短运行/停止时间、最大启动次数、启停/变频斜率、联锁、保护和故障逻辑 |
| 初始状态 | 模型事件开始时每台机组的启停、运行/停止累计时钟、频率/转速、可用性、控制模式、阀门位置、时间戳与质量标记；不得默认“全停且已满足最短停机” |
| 实际运行日志 | 带统一时钟的启停命令、回执、实际机组数、状态、频率/转速、进/出水位 H(t)、实测流量 Q(t)、功率/能耗、故障/联锁/手动介入和检修记录 |

当前 Adapter 只实验性映射 `inline_branch` + `aggregate_capacity` + 显式 availability + 有证据 head/reduction curve。`Capacity` 是处方上限，不是实际 Q。机组台数/启停不得直接转成 aggregate Capacity；跨流域或外部转输也不得冒充 inline Pump。没有真实 Q-H/效率曲线时，只能标记资料缺失，不得产生“保守默认曲线”。

## 实测、率定和独立验证资料

真实工程验证必须至少包含与模型时间窗重合的下列时序，并保留原始采样频率版本：

- 水位 H(t)：上/下游边界、关键节点、关键断面、每座参与验证闸的闸上/闸下和每座泵的进/出水位；
- 流量 Q(t)：外部边界、关键断面、支流/侧向汇入、参与验证闸泵和所有内/外转输项；
- 闸门：命令、实际开度/位置反馈、上下游 H、实测或有完整方法证据的结构 Q；
- 泵站：命令、实际机组状态/台数/频率、进出水位、实际 Q、功率/能耗、可用性、故障和人工接管；
- 观测站元数据：权威 ID、精确坐标/模型绑定、高程基准、仪器、采样方法、校准、精度/不确定性、质量码、时钟偏差和变更历史。

数据提供方必须标出原始缺测、无效、异常、超量程、仪器停机和人工更正；处理后版本必须保留处理标记和 lineage。重采样、时钟校正、插值和异常剔除方法必须在看到数据后由项目审批，本清单不预设方法或阈值。

率定与验证必须在建模前按水文事件/时段分开，记录选择理由，且不共用用于参数优化的观测样本。应覆盖项目要求的高/低流量、水位、闸门动作和泵启停事件。验收指标、站点权重、不确定性处理和阈值必须由工程责任人提供并审批；本文不填造默认验收值。

## MIKE11 或其他模型的交叉验证资料

如果使用 MIKE11 或其他第三方模型交叉验证，需要合法可用、不含未授权内容的导出物，并提供：

- 软件名称、精确版本/build、许可和导出权限证明；
- 可分发的河网、断面、粗糙率、边界、初始条件、闸泵设定、参数和计算时段导出；
- 完整 run/config/log 与结果文件 hash，以及模型成功/警告/失败状态；
- MIKE11 对象 ID 到 Dayu/D-Flow 节点、分支、断面、边界和闸泵 ID 的显式映射表；
- 单位、正方向、时区、水平 CRS、垂直基准、时间插值与空间取样差异；
- 对比位置/变量/时段、指标、阈值和差异解释的预注册方案。

第三方模型结果是交叉证据，不代替实测 H/Q/设备日志，也不能用来填补未知 Gate coefficient 或 Pump curve。

| 作业身份 | simulation/job/run ID、开始/结束时间、执行主机/容器标识、Workspace marker/manifest、输入快照 hash、冻结 DispatchPlan/model/control contract hash |

## 证据来源与责任链

每个 evidence 引用应解析到 manifest 中一条唯一记录，该记录至少回答：谁在什么时间、用什么设备/系统/图纸、以什么方法产生了哪个值；文件如何验证未被改动；是否经过转换；谁审查了该值；允许在哪些范围内使用。

建议按下列优先级选择来源，但任何来源都必须经工程责任人审查：

1. 现场测量、已校准传感器/SCADA 原始导出和经批准的竣工资料；
2. 厂商试验/性能资料和设备标定记录；
3. 有完整方法、输入、版本、hash 和不确定性的审批派生数据；
4. 隔离的合成 fixture，仅用于软件与数值 benchmark，不进入真实数据版本。

图纸与现场测量冲突、SCADA 与本地仪表冲突、不同高程基准冲突或同一设备有多份曲线时，不得自动选“最新”或取平均值；必须创建差异记录并由责任人选定适用版本。

- [ ] 所有 Gate 类型、几何、系数、开度、上/下游 H 和运行日志均有来源；
- [ ] 所有 Pump 的转输语义、机组数、Q-H/效率曲线、设计容量、进/出水高程、启停日志和实际 Q 均有来源；
- [ ] 边界 Q(t)/H(t)、初始条件、事件时窗和缺测处理完整；
- [ ] 率定与验证时段独立，指标/阈值已由项目责任人预先批准；
- [ ] Runtime、输入、日志、结果和报告的 provenance 链完整；
- [ ] MIKE11/第三方导出如被使用，已完成许可、身份映射、单位/基准/时间对齐和差异审查；
- [ ] 真实数据版本不含 `SYNTHETIC_ASSUMPTION` 值，不含未声明插值、默认曲线或默认系数。

以下任一情况都必须确定性阻断：关键数据缺失或被填造；设施/观测身份需要近邻推断；单位、方向、时区或基准不明；Gate subtype/系数无官方与工程证据；Pump Q-H 曲线、效率或转输语义不明；模型忽略实际存在的边界/侧向汇入/转输；率定与验证数据不独立；授权不明；或 Runtime/作业/结果 provenance 不完整。

资料验收通过仍只是进入建模的前提，不自动产生 `VERIFIED_*` Solver 能力，不解除 `DFLOW_RUNTIME_BLOCKED`，不打开 Dispatch `/runs`，也不授予 PLC/SCADA 设备控制权。
